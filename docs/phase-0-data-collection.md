# 阶段 0 数据采集方法

所有车辆操作必须在安全、静止、拉手刹的状态下完成。不要边驾驶边抓包、插拔或测试通话。

## 1. OPPO Find N6 与 CarLife

### 界面获取

1. 打开“设置 > 应用 > 应用管理”。
2. 找到“百度 CarLife+”或系统车机互联应用。
3. 记录应用名称、包名和版本号。
4. 打开应用内的“关于/设置”，检查是否提供无线连接、蓝牙连接或热点连接入口。
5. 在“设置 > 电池/应用耗电管理”中记录 CarLife 的后台活动、自启动和省电限制。

ColorOS 不同版本的菜单名称可能不同，以实际界面为准。

### ADB 获取

手机开启开发者选项和 USB 调试后，在电脑上运行：

```powershell
python scripts/collect_phone_info.py --report reports/phone-info.json
```

脚本会读取：

- 品牌、型号、系统版本和安全补丁。
- 包名中包含 `carlife`、`car`、`drive` 或 `auto` 的候选应用。
- CarLife 候选包的版本信息。
- 应用待机白名单中与车联应用相关的条目。

ADB 只能证明手机装了什么，不能单独证明无线 CarLife 一定可连接。最终仍需让 CarLife 与一个已知可用的 CarLife 车机或后续桥接板实际相连。

## 2. 君越车机软件与 CarPlay 版本

### 设置菜单

依次查看：

- “设置 > 系统/关于本机 > 版本信息”
- “设置 > 软件更新/系统更新”
- “设置 > 通用 > 关于”
- 车辆手册中的车机和 CarPlay 章节

拍照记录完整版本号，不要只记录最后几位。

### CarPlay 版本

大多数君越车机不会在普通设置页显示 CarPlay SDK 版本。该版本通常在 USB/iAP2 识别阶段由车机发送。获取方式：

1. 使用支持 USB role-switch 的协议分析仪记录 iPhone 与车机的 CarPlay 会话。
2. 使用已知可用的 CarPlay 转换器作为黑盒，在其调试日志中读取协议版本。
3. 在阶段 2 使用 Pi Zero 2 W 的 CarPlay 发送端，记录车机发送的识别信息。

没有上述工具时，该项应继续保持 `unknown`。

## 3. CarPlay 分辨率与刷新率

中控屏物理分辨率不等于 CarPlay 视频流分辨率。例如大尺寸 6K 中控屏仍可能只协商 `1920x720`、`1280x720` 或其他视频流。

需要从 CarPlay 会话的 AirPlay/RTSP 协商和视频流参数中获取：

- 视频宽度、高度和方向。
- 目标刷新率。
- H.264 档次、SPS/PPS 和色彩格式。
- 是固定全屏、分屏还是动态尺寸。

可行采集路径：

1. 阶段 2 开发板作为 CarPlay 发送端，让君越车机与开发板协商，并记录 CarPlay/AirPlay 参数。
2. 使用带调试日志的已知可用 CarPlay 转换器。
3. 使用能够处理 USB role-switch 和供电的 USB 协议分析仪。

在以上任一路径获得数据前，配置中的宽度和高度必须保持 `null`。

## 4. 触控、方控、麦克风和多媒体能力

先用 iPhone 做行为验收，全部在停车状态完成：

- 触控：点击、滑动、长按和多点触控。
- 方控：上一曲、下一曲、音量、语音键、电话键。
- 麦克风：拨打电话，确认车机麦克风上行和远端回听。
- 通话音频：拨入、拨出、挂断和恢复媒体。
- 导航音频：导航播报时媒体是否自动压低或暂停。
- 昼夜模式：开灯、关灯后 CarPlay 主题是否切换。

记录“可用/不可用/未测试”，不要把手册支持当作协议已经验证。协议级能力仍由阶段 2 的 iAP2/HID 日志确认。

## 5. 车口 50W 与实际 USB 供电

50W 通常是 USB-C PD 电源能力，不代表数据模式下开发板一定能获得 50W，也不代表 Pi 可以直接输入 PD 电压。

使用支持数据直通的 USB-C 功率计记录：

- 未连接设备时的电压。
- iPhone 进入 CarPlay 后的协商电压、电流和功率。
- 同时传输 CarPlay 数据时功率计是否会破坏连接。
- 手机充电稳定后是否发生重新协商或掉线。
- USB PD PDO 列表和实际选中的档位。

如果接上功率计后 CarPlay 不再工作，说明该测量方式不能用于最终链路；应改用带电源监测能力的 USB 协议分析仪。

## 6. 点火和插拔行为

连接不会反向供电的 USB 测量设备，依次记录：

1. 熄火锁车。
2. 解锁并打开 ACC。
3. 点火运行。
4. 熄火并锁车。
5. 锁车后 30 秒、1 分钟和 5 分钟。

记录车口是否断电、断点多长时间、再次上电是否自动恢复，以及 CarPlay 是否自动重连。

## 7. 写回阶段 0 配置

采集完成后更新：

- `config/vehicle.lacrosse-2025.json`
- `config/phone.primary.json`

然后运行：

```powershell
python scripts/check_phase0.py
```

只有检查器输出 `phase 0: PASS`，才进入真实协议适配开发。
